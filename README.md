# simple-calculator

# Multi-language Ping-Pong Calculator

A calculator where every operation is worked out by several languages and machines, and the answer only counts if they all agree.

- **Java** parses the sum (`*` and `/` before `+` and `-`), checks every answer against 64-bit arithmetic, and acts as referee for subtraction.
- **C** (through JNI, inside `calc.dll`) runs the same operation on three machines and compares them:
  - **RISC-V**: our own assembler and simulator, written in Python (`riscv/`)
  - **x86**: real instructions written as inline assembly in C
  - **WASM**: a small stack-machine interpreter running real WebAssembly opcodes
- If any machine disagrees, the calculator falls back to plain C, so the printed answer is always correct.
- **Optional ESP32 board:** shows the lowest 8 bits of each answer on 8 LEDs (on = 1, off = 0).

Supports `+ - * /` on 32-bit integers. Division is integer division (rounds toward zero). Overflow and division by zero are reported instead of printing a wrong number. Brackets are not supported.

## Requirements

- Windows 10/11, 64-bit (the C code uses Windows APIs)
- JDK 21 or newer (tested with JDK 26)
- gcc, 64-bit MinGW-w64: `winget install BrechtSanders.WinLibs.POSIX.UCRT`
- Python 3 with the `py` launcher

After installing anything, close and reopen PowerShell, then check:

```
javac --version
gcc --version
gcc -dumpmachine
py --version
```

`gcc -dumpmachine` must print `x86_64-w64-mingw32`.

## Repository layout

```
src/Calc.java        Java: parser, 64-bit check, referee, keyboard loop
src/test.java        optional automatic checker
native/calc.c        C: the three machines and the race (becomes calc.dll)
native/Calc.h        generated by javac -h
riscv/               our assembler, simulator, and run.py wrapper
esp32_bridge.py      sends each answer to the ESP32 (optional)
esp32/               ESP32 firmware, PlatformIO project (optional)
```

## Part A: Run it WITHOUT an ESP32

1. Download the ZIP and unzip it into a short path such as `C:\dev\calc`. Do not use Downloads: Windows can block compiled DLLs there.
2. Open PowerShell in that folder (`cd C:\dev\calc`).
3. Set `JAVA_HOME` for this window and check it:

```
   $env:JAVA_HOME = ((java -XshowSettings:properties -version 2>&1 | Select-String "java.home").ToString().Split("=")[1]).Trim()
   Test-Path "$env:JAVA_HOME\include\jni.h"
```

   The second line must print `True`.

4. Build:

```
   New-Item -ItemType Directory -Force build | Out-Null
   javac -h native -d build src\Calc.java
   gcc -Wall -Wextra -shared -I"$env:JAVA_HOME\include" -I"$env:JAVA_HOME\include\win32" -Inative native\calc.c -o build\calc.dll
```

5. Run it (always from the repository root):

```
   java --enable-native-access=ALL-UNNAMED "-Djava.library.path=build" -cp build Calc
```

6. At the `calc>` prompt try:

   | Type | You get |
   |---|---|
   | `10+2*3` | `16` |
   | `100/7` | `14` |
   | `-5+2` | `-3` |
   | `2000000000+1000000000` | `Overflow: answer doesn't fit in 32 bits` |
   | `1/0` | `Division by zero` |
   | `quit` | exits |

### What you see without a board

For every `+ - * /`, the terminal prints a race report, then the answer. Example for `4+3`, then `5-7` (the timings vary on every machine):

```
calc> 4+3
  add:
    Round 1 (operands in registers, instructions): RISC-V 1 | x86 1 | WASM 3 -> RISC-V & x86 tie for first
    Round 2 (memory in, memory out, instructions): RISC-V 4 | x86 3 | WASM 7 -> x86 wins
    Round 3 (constants, bytes of code): RISC-V 12 | x86 8 | WASM 5 -> WASM wins
  (info only, not judged: RISC-V sim round trip 220 ms, x86 native 1.5 ns)
7
calc> 5-7
  sub:
    Round 1 (operands in registers, instructions): RISC-V 1 | x86 2 | WASM 3 -> RISC-V wins
    Round 2 (memory in, memory out, instructions): RISC-V 4 | x86 3 | WASM 7 -> x86 wins
    Round 3 (constants, bytes of code): RISC-V 12 | x86 8 | WASM 5 -> WASM wins
  Java referee agrees: -2
  (info only, not judged: RISC-V sim round trip 215 ms, x86 native 1.4 ns)
-2
```

- The report goes to the error stream and the answer to the normal output. Both appear in the terminal.
- A line like `[riscv failed, using plain C]` means the RISC-V side did not run (usually `py` is missing, or you are not in the repository root). The answer is still correct.
- Each operation takes about a quarter of a second, because the RISC-V simulator is a Python program started once per operation. To skip the race and get answers instantly, run `$env:CALC_FAST = "1"` first, and undo it with `Remove-Item Env:CALC_FAST`.
- The three rounds are judged on instruction counts and code size. Timings are printed for information only, because a Python simulator cannot be fairly timed against real hardware. The answer is the same whoever wins.
- The calculator also writes the lowest 8 bits of each answer to `result.txt`. Nothing reads it unless you run the ESP32 bridge below.

## Part B: Run it WITH an ESP32 (optional)

First finish Part A, so the calculator already works. Then the LEDs show the lowest 8 bits of every answer: `12` is `00001100`, `-2` is `11111110`, and `300` shows as `00101100`.

**Hardware:** ESP32 NodeMCU 30-pin (CP2102), micro-USB data cable, breadboard, 8 LEDs, 8 resistors of 220 ohm, jumper wires.

**Wiring:** each LED is GPIO pin, then a 220 ohm resistor, then the LED's long leg, then its short leg, then the ground rail. Connect an ESP32 GND pin to the ground rail.

| LED (left to right) | GPIO | Bit |
|---|---|---|
| 1st | 23 | 7 |
| 2nd | 22 | 6 |
| 3rd | 21 | 5 |
| 4th | 19 | 4 |
| 5th | 18 | 3 |
| 6th | 17 | 2 |
| 7th | 16 | 1 |
| 8th | 13 | 0 |

**Steps:**

1. Plug the board in and check Windows sees it:

```
   Get-PnpDevice -Class Ports | Select-Object FriendlyName, Status
```

   You want `Silicon Labs CP210x ... (COM3)` with Status `OK`. If there is no port, use a different cable (some only charge), or install the "CP210x Universal Windows Driver" from Silicon Labs (right-click `silabser.inf`, Install). If your port is not `COM3`, change `PORT` near the top of `esp32_bridge.py`, and use your port number in the upload command below.

2. Install the **PlatformIO IDE** extension in VS Code and let it finish its first-time setup, then check:

```
   & "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe" --version
```

3. Flash the firmware (the first build downloads the toolchain and takes 10 to 25 minutes):

```
   cd esp32
   $pio = "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe"
   & $pio run -t upload --upload-port COM3
   cd ..
```

   - If it says `Connecting......`, hold the **BOOT** button on the board until it starts writing.
   - If it says `Cannot remove an outdated IDF virtual environment`, delete the folder it names, then run the command again.
   - When it finishes, all 8 LEDs flash once. That flash is the self-test, and it means the firmware is running and the wiring is right.

4. Install the serial library:

```
   py -m pip install pyserial
```

5. Terminal 1, from the repository root (leave it open):

```
   py esp32_bridge.py
```

   It prints `Watching result.txt - leave this window open`.

6. Terminal 2, from the repository root (run the Part A build first if you have not):

```
   java --enable-native-access=ALL-UNNAMED "-Djava.library.path=build" -cp build Calc
```

### What you see with a board

Type `10+2`. The terminal shows the race report and `12`. Terminal 1 prints `sent 00001100 = 12`, and the 3rd and 4th LEDs from the right light up. Each new answer changes the LEDs. Errors (overflow, division by zero) leave the LEDs showing the last answer.

Try `5*5` (`00011001`) and `-2+0` (`11111110`).

To stop: type `quit` in Terminal 2, and press Ctrl+C in Terminal 1. The LEDs keep the last answer until you press the EN button or unplug the board. Stop the bridge before flashing the board again, because it holds the serial port.

### How the LED path works

1. Java keeps the lowest 8 bits of the answer and writes them as binary text to `result.txt`.
2. `esp32_bridge.py` notices the file changed, reads the text as a binary number, and sends one byte over USB.
3. The ESP32 firmware reads the byte and switches each LED on or off by its bit.

Without a board nothing reads `result.txt`, so the calculator behaves the same. Do not start `esp32_bridge.py` without a board, because it stops with a "could not open port" error.

## Troubleshooting

| Problem | Fix |
|---|---|
| `Application Control policy has blocked this file` | Move the folder to `C:\dev` and rebuild |
| `gcc` not recognized | Reopen PowerShell after installing, or reinstall gcc |
| `jni.h: No such file` | `JAVA_HOME` is not set in this window (Part A, step 3) |
| `UnsatisfiedLinkError: no calc in java.library.path` | Build first, and run from the repository root |
| `UnsatisfiedLinkError` that mentions a method name | Rebuild in this order: `javac -h`, then `gcc` |
| `[riscv failed, using plain C]` | `py` is missing, or you are not in the repository root. Answers stay correct |
| `WARNING: A restricted method ...` | Harmless. `--enable-native-access=ALL-UNNAMED` silences it |
| Bridge: `could not open port` | Close any program using the port, and check the COM number |
| Bridge: `No module named 'serial'` | Run `py -m pip install pyserial` |
| LEDs show a mirrored pattern | The LED row is wired in the opposite order, so swap them end for end |
